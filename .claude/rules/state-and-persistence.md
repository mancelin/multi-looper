# Data Model, Stores & Persistence

Data model (`src/lib/types.ts`): a `Track` holds ≥1 named `Loop`s (`a`/`b` in seconds, kept sorted by `a`); `activeLoopId` picks the loop all A/B editing applies to. `extraMedia` is the timed image-or-markdown panel above the video: a gapless partition of the track into `ExtraMediaSegment`s (see playback-and-ui) that `patchDuration` re-spans through `clampSegments()` when a real duration lands late. Two older shapes reach us from storage: a bare `image` data URL, and a single untimed `extraMedia` object; `migrateExtraMedia()` turns either into one full-track segment on the way out of localStorage and PocketBase, and the legacy PB `image` field is blanked on the next write. `id` is a client uid; `pbId` is set once synced to PocketBase. Library order is the `tracks` array order (drag-and-drop in `Sidebar`); `sortOrder` mirrors it so PB restores it on load (new tracks get negative values to stay on top).

Three Zustand stores in `src/store/`:
- `library.ts`: tracks, current track, all track/loop mutations. Uses `subscribeWithSelector` so the persistence layers can watch it.
- `ui.ts`: playback UI state (playing, rate, loopEnabled), layout, modals, auth/account state.
- `sync.ts` + `guestPersist.ts`: two mutually exclusive persistence layers subscribed to `library`. Guests: library mirrored to `localStorage` (object URLs/`pbId` stripped) and local file blobs kept in IndexedDB (`lib/mediaStore.ts`, keyed by track id, pruned when tracks are removed); on boot/sign-out `restoreFileMedia()` re-registers the blobs and mints fresh object URLs. Signed in: per-track records in the PocketBase `tracks` collection (schema in `pb/pb_migrations/`), media files uploaded to PB storage; `sync.ts` diffs by fingerprint on store changes. PB enforces a per-user media quota (20 MB default, `MAX_USER_DATA_BYTES` env; 1 GB via `MAX_PREMIUM_DATA_BYTES` for users with the dashboard-only `premium` flag): `pb/pb_hooks/quota.pb.js` maintains the server-owned `mediaSize` field and rejects over-quota uploads with 400 "Storage limit reached"; the client toasts and parks refused tracks until deletions free space. Account count is capped too (`MAX_USERS` env, default 6000, 0 = off): `pb/pb_hooks/signup_cap.pb.js` refuses user creation (email sign-up and first Google sign-in) with 400 "Sign-ups are closed", which `sync.ts` turns into an auth-modal message pointing at guest mode. `bootAuth()` in `page.tsx` picks the mode; guest tracks can be imported at sign-in via `ImportModal`.

Ingest (`src/store/ingest.ts`): creates `Track` objects from YouTube URLs or dropped files. Local files are decoded with Web Audio into 600 max-abs peaks (`lib/peaks.ts`); YouTube gets synthetic peaks (`lib/youtube.ts`). Original `File` objects live in the in-memory `lib/fileRegistry.ts` (not serializable), and the sync layer reads from there when uploading media after sign-in. New tracks start with one full-track loop (a=0, b=duration). `addRecording` takes a mic take from `RecordModal` (capture in `lib/recorder.ts`: `MediaRecorder` for the blob, an `AnalyserNode` for the live meter) and adds it the same way, already decoded. Capture runs through a Web Audio chain: 30 Hz high-pass, then a gain ramp so the take opens and closes on silence instead of the capture device's click. The mic is opened by the modal, not by the record button (`Recorder.open()` vs `begin()`), and stays open across takes: opening a capture stream is what makes the beep/pop some hardware emits, so it has to happen while the user is still reading the dialog. Capture itself is ungated (nothing the mic hears once recording starts is ever dropped), and a take is a `kind:"file"` track indistinguishable from an upload apart from its `REC` tag. Takes are encoded to ogg/opus where the browser offers it (Firefox) and webm/opus otherwise (Chrome): Firefox's webm output is an unseekable live stream, which pins the playhead at 0 and makes every loop shortcut a no-op. `durationExact` additionally marks a duration that came from a real decode, so `onLoadedMetadata` can't overwrite it with what a container without a duration header reports. AGC and echo cancellation stay off (they pump and emit transients on music); the browser denoiser is the only one exposed, via `ui.recordDenoise`.
