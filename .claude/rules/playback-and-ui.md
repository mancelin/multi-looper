# Playback, Loop Editing & UI

Playback (`src/lib/player/controller.ts`): singleton `player` outside React — the single clock source per track. Backends: YouTube IFrame API (`controls:0`; app transport is the only control) or a `<video>` element for local files (also audio). A `requestAnimationFrame` tick reads media time and enforces the A→B loop; playhead/time readout update **imperatively** via `player.onTime()` listeners so React never renders at frame rate — keep it that way. Real durations arrive late (YT placeholder 210s, failed decode 120s) and flow through `library.patchDuration`, which re-clamps loops and keeps full-span loops full.

Loop editing: all clamped A/B operations (set/nudge, min gap 0.05s) live in `src/lib/loopEdit.ts`, shared by UI buttons and keyboard shortcuts (`components/ShortcutsProvider.tsx`). Don't patch `a`/`b` directly from components — go through `loopEdit` or `library.patchActiveLoop`.

UI composition: `app/page.tsx` → `TopBar` + `Sidebar` (library) + `PlayerMain` (`TrackHeader`, `ExtraMediaPanel`, `VideoPanel`, `Waveform`, `ExtraMediaTimes`, `LoopStrip`, `LoopTrim`, `Transport`) + modals. `Waveform` paints bars inside the loop region with the track accent color. The column packs from the top — nothing pins the transport to the bottom, so a track with no extra media puts its controls straight under the waveform instead of across a gap; `VideoPanel.fitVideo` reads the leftover height from the packed children rather than from that gap.

Extra media (`components/player/ExtraMediaPanel.tsx`): optional companion content above the video, available on every track kind (YouTube, file, recording), and **timed**. `Track.extraMedia` is a list of `ExtraMediaSegment`s that PARTITIONS the track — sorted, gapless, first starting at 0, last ending at `duration` — so exactly one is showing at any moment; the panel renders the segment the playhead is inside. Each segment holds one medium: `{type:"image", src}` (downscaled data URL, set by click/drop/paste; drop and paste are handled by `PlayerMain`) or `{type:"markdown", text}` (notes edited in `MarkdownEditor` — textarea + formatting toolbar + preview tab, Ctrl+Enter saves — and rendered by `MarkdownView`); a segment with no `media` yet shows the add buttons in place of its content. Markdown goes through `react-markdown` + `remark-gfm`, which drops raw HTML, so no sanitizer is needed; element styling lives in the `.md-body` block of `globals.css` (Tailwind v4 here has no typography plugin). Both destructive actions go through `ConfirmRemoveExtraMediaModal` (`ui.confirmExtraMedia`, same shape as the track-removal confirm): `mode:"media"` for the panel's × (clears the media, leaving the segment) and `mode:"segment"` for the times menu's Delete (drops the segment itself). Clearing the last segment leaves the track with no extra media at all. Panel heights are per-track overrides in `lib/extraMediaSize.ts` (localStorage, discarded on window resize).

Segment times (`components/player/ExtraMediaTimes.tsx`, folded by default via `ui.extraTimesOpen` so it costs one header row): a proportional strip of the segments whose **shared edges** are dragged to retime them — an edge belongs to the two segments it separates, so moving it retimes both and no gap or overlap can be opened. "Add at playhead" carves the segment under the playhead in two, the new half empty; "Delete" (behind the same confirm modal) drops a segment and hands its time back to its neighbour, or clears the track's extra media when it is the last one. All the clamped segment math lives in `lib/extraMedia.ts` (pure, `MIN_SEGMENT` = 0.25s — short because mic takes are short) with the store-bound wrappers in `lib/extraMediaEdit.ts`, the `loopEdit.ts` split; don't write `extraMedia` from components. The playhead marker and the strip's ruler follow `player.onTime()` **imperatively**, and React only re-renders when the playhead crosses a boundary or the split button flips usable — same rule as the waveform.
